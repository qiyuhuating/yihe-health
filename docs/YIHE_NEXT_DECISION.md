# Yihe-Next 架构决策（提案）

状态：待维护者审查。相关议题：[Issue #18](https://github.com/qiyuhuating/yihe-health/issues/18)。

当前生产架构仍为 [MySQL 单库](ARCHITECTURE.md)。本提案不授权生产
PostgreSQL/S3 部署，不改变设备、会话或权限契约，不改变现有发布门禁。
独立实验使用合成数据，不进入生产构建。

## 决策与实施顺序

| 阶段 | 选型及边界 | 生产晋升条件 |
| --- | --- | --- |
| 0 | 保持 Go；先测定连接、事务和磁盘基线。S3 兼容对象存储承载密文、Valkey 承载短期状态的迁移分别评审 | 图片哈希与解密校验、可恢复迁移账本、明确唯一权威元数据；会话撤销及防重放故障语义一致 |
| 1 | 独立 SOS / 遥测 JetStream 部署、磁盘 WAL、幂等消费者；时序投影仅作可重建影子读 | 三副本真实故障域测试；队列持久化、业务事务和通知回执分开；重复、乱序、撤权、重绑和过载验证 |
| 2 | Rust 网关及规则引擎，复用 yihe-core；保留旧 HTTP/JSON 设备接口；二进制协议先在模拟器与影子网关验证 | 原 API、授权、规则和错误语义差分通过；真实设备、桌面诊断及打包可用；CGO 移除须有替代路径 |
| 3 | PostgreSQL OLTP 迁移候选、持久告警状态机、独立通知通道、信封加密、多故障域部署 | 数据迁移可校验、单写者 fencing、备份恢复、真实故障演练及 60 分钟满载证据 |

## 不可破坏的契约

1. 设备身份与绑定 epoch 在接入和业务消费阶段均须按权威状态校验。
   缓存不可用或撤权状态未知时，不得仅凭仍有效的旧令牌放行。
2. 不使用 Redis/Valkey 的非同步复制或 TTL 作为唯一防重放凭证。
   已提交会话撤销必须在故障转移后继续有效。
3. 发布 ACK、业务提交回执、通知送达回执是三种不同状态。
   发布 ACK 不能被描述为已创建告警或已通知护理人员。
4. 消费者以设备、epoch、request ID 为持久幂等键，存储认证载荷摘要。
   相同键不同内容须拒绝或进入审计隔离；业务变更与回执必须同事务提交。
   Broker 短期去重窗口不能代替此约束。
5. SOS 不受普通遥测队列容量限制，独立计算、连接及磁盘预算；
   无法获得可靠 ACK 时返回可重试的未确认结果，由设备保留请求。
   有限资源不能承诺任何情况下无限接纳或绝对零丢失。
6. 不建立双向双写。切换前按快照水位回填，再连续同步变化、
   验证加密内容及引用、停止旧写者、排空并建立新写者 fencing。
   切换后旧系统只读；回退需先重放已确认写入并核对差异。
7. 业务数据库、消息日志和加密对象的备份、密钥生命周期和恢复必须
   同时纳入验收；任何单项验证不能代替端到端恢复。

## 量化验收

遥测 ACK P99 < 2 ms、SOS 入队 P99 < 10 ms、RSS 降低 50% 是
设计目标，而非已取得数据。测试应固定负载、初始积压、同步持久化、
硬件、时钟、故障域与客户端语义，记录 P50/P95/P99、失败与重试、
队列积压、真实提交时间和通知回执。使用模拟器与实际设备分别验收。

RPO=0 仅能针对已确认、在定义故障模型内同步复制的写入声明；
RTO < 15 s 必须从故障发生至恢复可用的实际演练测得。双 AZ 不等于
三个独立投票故障域，不得由单机三进程结果推断真实跨 AZ 可用性。

## 已隔离的实验

[JetStream transport experiment](../experiments/jetstream/README.md)：
使用独立测试模块验证真实 broker 的容量、提交后 ACK 与重投递语义。
该模块复用真实 MySQL 业务持久化函数，在隔离迁移库中验证加密低风险遥测、原子回执、绑定版本与授权代际检查。它不接入生产 HTTP 路由，不安装生产迁移，也未实现设备接入认证、生命体征及 SOS 业务消费。
同一实验模块另含 RustFS/S3 加密对象影子复制：原始 BLOB 保留，条件 PUT 和下载认证完成后，以原有锁序复核源版本并发布影子账本。真实 RustFS/MySQL 测试通过，但尚不授权生产存储切换。
Valkey 会话影子迁移保留原加密载荷和绝对过期时间，MySQL 元数据投影与原会话写入、撤销同事务更新；每次影子读取仍实时校验 MySQL 与二次验证版本。真实 Valkey/MySQL 撤权测试通过，尚未切换生产会话后端或测试实际跨节点故障转移。
Phase 2 已建立独立 Axum/Tokio 网关，生产环境仍保留 Go 作为唯一业务写入者，原生 Rust SOS 字段解析与直接 Yihe-Core 统计经实际 Go 实现差分验证；独立 MySQL 迁移库 HTTP 差分验证签名、重放和 SOS 重试。独立测试模式已实现签名步数上报的 Rust 原生认证、居民/设备锁后复核、共享 nonce 表与步数/心跳原子事务；独立 Rust JetStream 生产者已实现步数请求的事务性 Outbox、Go 加密事件兼容、PubAck 后条件标记与故障重发；已增加复用 SQL 池和 NATS 长连接的持续发布实验及独立 Protobuf/Ed25519 步数协议，真实模拟器与 Go 独立编码器互操作通过。Rust 原生消费者已完成步数事件的授权复核、Go 兼容回执、业务事务及提交后 ACK，实际故障重投通过。Yihe-Core 增量心率窗口、七类规则候选及状态转换已通过 Go 差分；独立体征流已验证 Rust 原生心率/血压加密 ratepre 写入、告警快照与回执原子事务，并通过真实已提交测量记录的有界增量重放；独立 Protobuf/Ed25519 体征签名入队、体征 Outbox、固定容量常驻统计投影及无定位 SOS 原生告警/加密通知/回执事务已实现实验路径；生产 health_sample 修订时钟、完整规则持久化、SOS 签名接入和通知发送仍未迁移，低风险步数事件不得伪造生命体征输入。完整设备协议、SOS、生产公钥配置、全局积压保护、生产路由及安全配置仍未迁移。详见 [Rust gateway experiment](../experiments/rust-gateway/README.md)。
