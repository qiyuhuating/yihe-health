# 健康同步及统计副本保护

迁移 0041 为健康变化流、最新样本和日统计结果增加密文列。

| 表 | 认证范围 | 保留的查询字段 |
| --- | --- | --- |
| `health_change` | 版本、住养老人 ID、样本 ID | 归属与同步游标 |
| `health_sample_latest` | 住养老人 ID、序列键、版本 | 归属、序列和版本 |
| `metric_daily` | 缓存键、计算版本 | 时间窗口、归属、状态和计算版本 |

配置数据密钥后的写入在业务事务中封装载荷，旧载荷列置为 SQL NULL。授权读取先验证归属，再读取需要的载荷。缺少 reader、认证失败及不同记录之间的密文互换都会导致读取失败。新旧载荷可在上线和回填期间并存。回退 SQL 保留数据列，回退到旧应用前须使用匹配的备份恢复。

## 回填及轮换

在后端模块目录构建 `go build -o protect-health-projections ./cmd/protect-health-projections`，使用受限的 `MYSQL_DSN_FILE` 和 `DATA_ENCRYPTION_KEY_FILE` 注入实际部署的值。默认模式扫描待处理行数并验证各表首条现有密文。

执行前停止相关写入端，验证匹配的备份可恢复，并以 `rekey-data` 的只读模式核对所有现存密文及 reader。每次显式执行 `protect-health-projections --apply --limit 100` 会在三表合计迁移至多指定的行数，允许范围 1–1000。每条在行锁内重读并写入，原同步游标、缓存版本与业务字段保持原值。部分完成返回非零和剩余行数，重跑接续迁移。留存最终扫描的三表剩余量和 `rekey-data` 的全量报告。

三列纳入现有 `rekey-data` 的预检、CAS 重封装和认证复查。旧备份仍使用其匹配的密钥，最终密钥撤销由资产盘点与恢复验收决定。

## 原始样本

迁移 0042 为 `health_sample` 增加密文列。配置数据密钥后，采集事务以样本 ID、长者 ID 和版本游标为认证范围，原始载荷列置为 SQL NULL，对应测量值生成列也为空。原有归属、绑定纪元、时间、来源、指标和删除标记继续支持索引筛选。重复版本冲突比较使用解密后的原载荷；覆盖较旧记录前仍须认证原密文。

历史明文以 `protect-health-projections --samples` 只读盘点，按上述停写、备份及完整 reader 审查执行 `protect-health-projections --samples --apply --limit 100`。完成后核对原载荷列和测量值生成列的残留数量，并使用 `rekey-data` 验证第 32 个密文列。尚未回填的历史值仍能走原有覆盖索引。

统计、日结果、最近值和读端基线在授权及索引筛选后解密。规则基线在同一个查询快照内合并历史明文的 SQL 统计和密文的应用端总体统计，保留原来源匹配、时间窗口与时区剔除。长窗口性能需在历史样本规模下独立测量。旧数值上报表及历史资产继续按数据分类验证。

## 旧式心率与血压记录

迁移 0043 为 ratepre 增加 measurement_cipher。配置密钥后，两项读数在同一上报事务中加密，原 hr、bp 列置空。密文认证记录 ID，读取时同时核对长者和设备。缺测值保留为空。

使用 protect-health-projections --legacy-vitals 盘点历史行。在完成上述停写和备份验证后，可加 --apply --limit 100 分批回填。完成后复查剩余行数，并使用 rekey-data 核对第 33 项 ratepre.measurement_cipher。
