# MySQL 图片密钥轮换

迁移 `0039_mysql_image_payload_generation.sql` 增加图片密文版本表。已有加密图片仍可读取。每次轮换写入独立的不可变密文版本，再在同一个 MySQL 事务中切换当前版本并移除旧版本。图片名及其认证范围 `image:<name>` 保持不变，头像、评论、公告、相册引用和下载地址继续可用。事务保存原逻辑目录的摘要、大小与创建时间。已有回收流程删除逻辑图片时也删除对应密文版本。

先备份数据库并验证可恢复。部署支持迁移 0039 的程序，将所有图片写入者切换为使用含旧 reader 的新 active keyring。核对各实例后执行工具。通过 `MYSQL_DSN_FILE` 和 `DATA_ENCRYPTION_KEY_FILE` 提供受限配置，后端目录可用 `go build -o rekey-images ./cmd/rekey-images` 构建工具。

```text
rekey-images
rekey-images --apply
rekey-images
```

默认只读扫描全部逻辑图片，包括尚无目录的孤立图片。apply 前完成全量认证、核对目录摘要、检查缺失引用及孤立版本。程序按页读取和逐图提交，事务遵守备份租约并比较当时的密文、版本和目录。中断后保留已提交的图片，重新扫描可续跑。遇到备份租约、并发回收或目录改变，查明状态后重跑。参数 `--max-images` 控制每次扫描的上限，`--timeout` 控制整个操作的期限。汇总报告不包含图片名、内容或密钥。

最终同步停止仍可能写旧格式或旧密钥的实例，再用仅含目标 reader 的配置重扫。现场需要保留旧配置以应对失败恢复。正式移除旧密钥仍须检查用途清单、历史导出、备份、binlog、恢复版本及其他加密字段。图片报告的 `retirement_authorized` 保持 false。回到 0039 之前的程序须从匹配版本的备份恢复，并核对备份后的写入。
