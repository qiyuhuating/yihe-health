# SOS 故障恢复演练

在装有 MySQL 8 原生工具、Python 3.10+、项目要求的 Go 版本及 Go 竞态检测所需 C 编译器的测试主机上，从干净的已提交源码运行。

```powershell
python scripts/reliability/sos-outage-drill.py --mysql-bin 'C:\Program Files\MySQL\MySQL Server 8.0\bin' --report-dir 'E:\private-drill-reports'
```

为报告目录使用只有当前用户可以读取的路径。每次运行会在该路径新建独立子目录，使用新建的 MySQL 数据目录及随机回环端口，并构建和启动此提交的后端。运行结束后停止本次启动的进程，保留数据和诊断日志供复核。该目录含合成账号和会话凭据，只需共享经核对的摘要。

默认验收覆盖以下场景。

- 10 轮 MySQL 真实停止和重启。数据库停止后，已提交请求的重试和新 SOS 都须收到 HTTP 503，且响应不能带成功标记。重连后核对既有记录、重试请求的事件 ID 及老人绑定。
- 10 轮后端强制退出和重启。以原请求 ID 重放，核对事件 ID、接收记录和短信发件箱行数，验证没有额外记录或孤立发件箱条目。
- 同时发起 100 个不同请求 ID 的签名 SOS，再并发重放其中 10 个 ID 共 100 次。每个 ID 初次提交须产生一个独立事件，重放须返回原事件 ID 和重复标记。
- 10 轮回环 TLS 网关超时和签名回执重放。复用完整链路测试核对失败记录、送达、人工确认、处理和复核。

`summary.json` 记录源码提交、完成轮次、数据库行数和清理状态。退出码为 0 且摘要标为 `passed` 方算通过。可用 `--rounds` 和 `--gateway-rounds` 缩小排查范围，正式验收使用默认轮次。此演练使用合成设备和回环通知网关。历史 PG/S3 的迁移和恢复、真实手表及长时容量验收分别记录。
