# 备份与恢复 · MySQL 8.4 单库

颐和 2.1.0 使用 MySQL 8.4 保存业务数据、健康记录、加密图片、会话、审计和通知 outbox。PostgreSQL、S3 和本地图片目录仅可能属于历史部署，不是当前在线恢复依赖。升级旧系统之前，仍须保留对应旧库及原始图片。

## 必须保护的资产

| 资产 | 备份与恢复要求 |
| --- | --- |
| MySQL 数据库 | 全部业务记录、迁移账本、设备绑定、告警、审计、通知状态以及 `image_payload` BLOB |
| `DATA_ENCRYPTION_KEY` 和轮换 keyring | 独立受控托管；恢复时使用对应历史密钥，丢失后已加密数据可能无法恢复 |
| 部署配置与通知网关凭据 | 保留非公开的受控副本，绝不混入公开源码、SQL 或诊断日志 |
| 历史 PostgreSQL/S3/图片来源 | 在迁移、回退或保留期仍需要时单独备份，不作为现行在线服务组件 |
| 监控历史 | 可辅助故障分析，不能替代原始业务记录和人工处置证据 |

## 一致性备份

制定明确的 RPO/RTO、加密存储、保留期、异地副本、权限管理与备份失败告警。全量备份必须覆盖 MySQL 表结构、索引、迁移版本、加密 BLOB 和重要事务记录。需要时间点恢复时，另行保留并演练 MySQL binlog 重放。

在已经配置安全数据库凭据和隔离备份目录的环境中，可参考：

```sh
mysqldump --single-transaction --quick --routines --triggers --events --hex-blob \
  --set-gtid-purged=OFF --databases yihe > /secure-backup/yihe.sql
```

事务快照不能自动覆盖并发 DDL、跨系统迁移及旧图片文件复制。正式版本升级、密钥轮换或图片迁移前，需停止旧写入者、确认备份和恢复路径。备份包含敏感个人信息，必须加密、限制访问，并且不得上传公共仓库。

## 隔离恢复演练

1. 验证备份时间、完整性摘要和加密状态，并导入独立的 MySQL 8.4 测试实例，绝不覆盖仍在运行的生产数据库。
2. 恢复匹配的加密密钥和必要部署配置，隔离真实短信/电话网关，防止历史 SOS 意外重发。
3. 核对 `schema_migrations`、账号与设备关系、照护事件、待发送通知、审计历史、健康记录，以及 `image_blob` 与 `image_payload` 的关联和认证完整性。
4. 验证授权登录、健康数据读取、图片上传下载和数据库重启。记录实际 RPO/RTO、恢复时间及缺失记录。
5. 计划切换为生产库时，先停用旧写入者，核对恢复点以后的业务写入、设备 `requestId` 幂等键与通知网关状态，避免重复派单。
6. 如仍需导入旧 PostgreSQL/S3 数据，按 [MySQL 单库迁移](../MYSQL_ONLY_MIGRATION.md) 在隔离环境执行；禁止将旧分析库直接替代业务数据库。

仓库提供 [独立 MySQL 恢复演练脚本](../../scripts/reliability/run-mysql-restore-drill.py)，运行前必须将 `TEST_MYSQL_DSN` 配置为**可销毁的测试实例**。真实数据库测试跳过或失败不能算通过。

## 故障处理边界

- MySQL 不可用时，业务写入必须返回明确失败，不能将缓存结果当作成功提交。
- 现行加密图片 BLOB 属于 MySQL 备份，旧本地目录或对象存储只用于历史迁移、回退。
- 网关接受请求不证明家属收到通知；Prometheus 告警也不证明值班人员已经响应。需要独立的人工备用救援流程。
- systemd 或 Compose 自动重启不等于跨主机高可用。应用回滚也不会自动还原数据库结构或保留升级后新增的业务数据。

仅在历史副本已完成迁移验证、恢复演练且符合保留期制度后，才考虑正式退役旧库与密钥。删除旧文档不意味着可以删除数据库迁移 SQL、回滚脚本或历史备份。
