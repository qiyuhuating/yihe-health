# 前端交接说明

## 当前实现

- 页面包括公开站点、居民端、工作人员端和管理入口。
- HTTP 模式通过同源 `/api/v1/` 访问服务，使用浏览器会话 Cookie、CSRF token、请求超时、轮询、结构校验和并发版本字段。
- `npm run build` 生成 HTTP-only `dist/`，构建时移除演示账号、演示居民数据和演示登录逻辑。生产只发布 `dist/`。

## 接入责任

前端已经定义请求和响应约定；后端仍需实现身份认证、授权、数据持久化、事务、版本冲突、幂等记录、审计、限流和错误响应。静态站点与 API 通过 HTTPS 同源部署，浏览器端不配置服务端密钥。

完整接口表、字段约束、安全要求及验收步骤以 [后端接入交付说明](backend-integration.md) 为准。部署操作以 [发布与回滚手册](release.md) 为准。

## 建议接手顺序

1. 后端与前端共同确认接口契约及认证角色。
2. 后端实现 `/session` 和 `/care/snapshot`，先联通登录与只读页面。
3. 按交付说明逐项完成写操作、版本冲突和幂等语义。
4. 完成权限、跨用户隔离、异常响应和发布环境联调后，再安排生产发布。

本仓库现有单社区 SQLite API 与真实 HTTP 合成数据验收；没有生产凭据或生产数据。运行见 `backend/README.md`，正式运营部署仍需验收。
