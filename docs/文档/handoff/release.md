# 发布与回滚手册

## 发布前准备

- Node.js 18+、Python 3，以及可用的 HTTPS 域名和后端服务。
- 后端按 [后端接入交付说明](backend-integration.md) 提供 `/api/v1/` 接口。
- 静态站点与 API 使用同一来源；服务端不得把 API 错误路由回退成 HTML 页面。

## 构建发布包

在仓库根目录执行：

```sh
npm run build
```

构建输出位于 `dist/`。仅将该目录内容部署到静态站点根目录，不发布仓库源码、测试夹具或开发配置。构建脚本会生成 `dist/release-manifest.json`，记录发布文件的 SHA-256 摘要；归档该清单以便核对构建产物。

## 部署要求

1. 配置 HTTPS，并保留 HTTP 到 HTTPS 的 301 跳转。
2. 将 `/api/` 同源反向代理到后端；代理需正确传递 Host、转发协议和客户端地址。
3. 为静态资源设置仓库 `部署/headers` 中列出的安全响应头。Nginx 可参考 `部署/nginx.conf.example`，替换域名、证书、静态根目录和后端 upstream 后再使用。
4. 确认 HTML 使用 `no-store`，API 返回 JSON，Cookie 使用 `Secure`、`HttpOnly`、合适的 `SameSite` 和路径设置。
5. 确认 `/api/v1/` 错误不会被 SPA/静态站点规则改写成登录页或首页。

## 发布验收

- HTTPS 页面能加载，HTTP 请求会跳转 HTTPS；安全响应头实际出现在响应中。
- 未登录访问受保护页面会回到登录入口；登录后仅显示当前身份有权查看的数据。
- 刷新、退出、过期会话、CSRF 拒绝、并发版本冲突和重复提交均符合接口交付说明。
- 浏览器网络面板中 API 请求均为同源 `/api/v1/`，没有演示数据、服务端密钥或生产凭据。
- 生产构建检查和后端联调验收均通过后，记录构建版本、manifest 摘要和发布时间。

## 回滚

保留当前版本 `dist/` 归档及其 manifest。出现发布故障时，将静态站点切回上一份已验收归档，并确认 API 版本兼容；若后端数据结构已变更，先由后端执行兼容回退或前向修复，再恢复流量。回滚后重新核对登录、快照读取和关键写操作。

## 当前限制

仓库提供前端构建、Nginx 示例及单社区 Python/SQLite 后端；不包含生产数据库、TLS 证书、域名、CI/CD 发布目标或生产密钥。上线前须按 `backend/README.md` 配置服务、生产容器、备份与反向代理，并完成真实环境验收。
