# 按影响排序的修复与验收

前端呈现状态；Demo 模拟同一 API 契约；后端拥有真实身份、信号、事件与审计。沿用现有 Transport、Adapter 和运行模式。

## 首批：错误语义与会话

1. 持续信号不能因 resolved / false_alarm 静默。当前实现为下一次扫描生成关联旧事件的新 incident，不等待复核计时；恢复信号才停止生成。真实复核延迟后续由后端定义，不能无限延迟。
2. 提醒按页面访问独立呈现。全局 presented 只记审计；接单是当前轮次的共同 acknowledged。后续恶化必须再次提醒。展示回执原子校验实际 cycle。
3. HTTP 快照携带 serverTime；时限显示与排序基于服务端时间和单调计时。真实过期、离线及用药窗口由后端判定。
4. 401 在原页面锁定并重新登录，同账号保留内存草稿与旧 revision；换账号清除草稿。HTTP 管理端 15 分钟空闲锁定并请求吊销，网络失败报告退出未确认。后端另行实施会话 TTL。
5. 离线前危险采样仍显示危险颜色，附当前状态未知；离线不等于健康恢复。
6. 登录入口角色不符时撤销服务端会话；撤销失败必须明确报告，清除内存身份和 token。

已有并发修复：居民 revision 比较交换、第一联系人局部 PATCH、用药意图幂等。HTTP 接入必须实现新契约，不能只改前端就宣布闭环完成。

## 第二批：契约、隐私和质量约束

- 同一套契约场景跑 Demo 与 HTTP：居民冲突、旧 cycle、重复意图、时间窗、字段限制和错误码。HTTP 测试使用可控服务实现，而不是只核对发送参数。
- 导出改为服务端授权、范围限制与审计；定义自由文本处理。打码明确只是显示功能，电话号码、搜索与备注另行验收。
- 渲染改为可审查的自动转义机制；静态字符串扫描不能证明无 XSS。
- 使用允许列表中的机器错误码和字段错误，不能直接把任意服务端正文显示给用户。处置记录为空等常见错误先在客户端校验。
- 合并业务元数据来源与 CSP 配置，加入漂移检查。地图移除 HTML style 属性后再收紧 style-src-attr，并验证各浏览器定位正常。
- 清除陈旧注释、检查器引用和发布包无用文件；核对源码、npm 元数据与发布压缩包的 LICENSE。当前 package.json 已是 MIT，不能继续按 UNLICENSED 报告。

## 第三批：最小后端与规模

- Session、居民 PATCH、事件流转、设备事件、用药、审计、NotificationService 假实现。
- 定义数据保留和分页；不能删除开放事件或活跃信号引用。Demo 明确丢弃历史的边界，生产审计按正式政策保存。
- 轮询增加失败退避和条件读取；revision 不变时避免整包渲染。后台恢复先读服务端最新时间与状态。
- 网关级故障归并，保留居民级危险信号，避免归并掩盖危险。
- 短信供应商接入在真实网页闭环稳定后进行；高级报表和 AI 分析暂缓。

## 体验验收

居民端保持新中式、管理端保持工作台。适老化重点改为实际字号、缩放后溢出以及明暗主题对比度测量，不重复泛化为基础无障碍重做。居民关键正文以 16px 为最低验收目标，重要读数与操作使用更大字号；同时保留焦点、触控和减少动画支持。

破坏性场景：双标签旧资料提交、cycle 1 展示后升级 cycle 2、持续危险错误结案、写成功响应丢失、重复登记、后台恢复、系统时钟跳变、存储配额、畸形数据、编辑中会话失效、重新登录不同账号。
