# 当前架构

纯 HTML/CSS/JavaScript，无框架迁移或运行时依赖。

| 模块 | 职责 |
|---|---|
| 数据/residents.js、脚本/metrics.js | 虚构居民种子、演示指标规则 |
| 脚本/care-api.js | 页面稳定调用面；按显式运行模式选择演示实现或 HTTP 适配器 |
| 脚本/care-http-adapter.js、脚本/care-runtime-config.js | HTTP 请求、错误归一化及演示/服务模式选择；不含服务端实现 |
| 脚本/care-transport.js、脚本/care-session.js | 同源会话、CSRF、请求超时、状态码映射与登录/退出 |
| 工具/build_frontend.py | 构建仅支持服务接口的 dist 发布包，剔除演示数据与凭据，检查资源引用并生成文件清单 |
| 脚本/care-ui.js | 转义、安全联系方式、指标上下文、事件与趋势展示 |
| 脚本/resident-care.js | 居民三个页面及表单 |
| 脚本/staff-care.js | 工作台、预警处置、居民、地图、设置 |
| 脚本/theme.js | 全站主题及跨标签同步 |
| 脚本/audit.js | 旧本机日志兼容与保留记录一致性校验 |
| 样式/reconstruction.css、样式/community.css | 既有视觉基础与本轮业务布局 |

初始化顺序：公共工具、居民数据和指标规则先于 CareAPI；CareAPI/CareUI 先于页面控制器。管理员凭据配置先于登录脚本。具体加载标签由静态检查验证。

源码默认 `mode: demo` 使用本机模拟聚合。正式构建只允许 `http`，业务记录和会话均通过同源 API 获取；网络错误不会回退到模拟数据。居民 ID、工作人员 ID 来自服务会话，前端不提供身份切换。所有权限必须由服务端执行。完整契约见 [前端交接说明](handoff/frontend.md)。

HTTP 请求有统一超时，不自动重试写操作。快照在发布给页面前校验引用、数组、状态、版本与时间；非法数据暂停业务操作并提供重新读取。401 隐藏受保护界面并回到登录；409 保留处置输入，允许在弹窗内重新读取版本后提交。轮询在上次完成后计时，后台页和断网页暂停，恢复后再读取。截图与原有响应式/键盘回归同时覆盖前端发布流程。

## 演示模式的写入与同步

`yihe-community-v1` 是单条 JSON 聚合，包含 version、revision、residents、events、conditions、logs。写入通过同源 Web Locks 串行化：读取最新状态、校验、一次持久化，成功后才发布页面更新；存储失败拒绝操作。事件独立 revision 防止过期操作覆盖。同窗口通过 care:change、跨标签通过 storage 通知刷新。页面按读取请求序号丢弃较晚到达的旧请求；恢复旧备份导致 revision 下降时，仍以最新读取到的实际存储为准。

读入和提交前都校验聚合、居民、用药、联系人、趋势、事件引用、状态、负责人、时间、历史、提醒及检测条件。无效结构拒绝整个操作并保留原始存储，不自动覆盖为演示种子。缺失/非有限数值的指标作为 unknown 展示，并形成待核实的健康事件；离线时不把先前健康异常标记为信号恢复。

DATA_INVALID、STORAGE_UNAVAILABLE、ENV_UNSUPPORTED 错误由页面统一呈现；暂停业务操作并提供重新读取。居民端保留紧急拨号；存储恢复后解除暂停。不支持 Web Locks 或非安全上下文时不退回无并发保护的写入方式。一般表单校验或配额失败则保留输入，不显示保存成功。

事件生命周期为 new → claimed → processing → resolved / false_alarm / escalated。升级重新指派负责人但仍未完成；信号恢复只写历史，不自动关闭。重复持续信号去重；恢复后复发可生成新事件，恶化可再次提醒。页面提示按通知轮次留痕，但 externalDelivered 始终为 false。

仅迁移能按居民 ID 可靠匹配的旧姓名、年龄和联系人。旧服药输入不擅自变成已确认用药计划。旧聊天、密钥等浏览器键未删除，也不再由当前页面读取。

模拟器只在页面运行时推进采样。趋势来自实际生成的模拟采样，不预填历史曲线。真实部署必须由服务端接管检测、授权、并发与持久化。

本机审计新时间戳使用 UTC ISO 8601，既有时间与哈希链保持原值。损坏的 JSON 不会被当成空日志覆盖。显式清空在一次写入中保留“清空本机审计记录”操作，保存失败则此前日志完全不变；此后只能校验保留记录。
